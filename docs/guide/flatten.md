### Intersection Types (`#[serde(flatten)]`)

A struct field marked `#[serde(flatten)]` is lifted into the parent type as a TypeScript intersection (`A & B`) and a Zod `.and()` chain, instead of a nested object. This is the idiomatic way to compose a common set of fields with a discriminated union.

```rust
#[model_schema()]
#[derive(Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct DataElementSampleValueEntry {
    pub data_element_id: String,
    #[serde(flatten)]
    pub variant: DataElementSampleValueVariant,
}

#[model_schema()]
#[derive(Serialize, Deserialize)]
#[serde(tag = "dataType")]
pub enum DataElementSampleValueVariant {
    Alphanumeric {
        #[serde(rename = "sampleValues")]
        sample_values: Vec<String>,
    },
    Numeric {
        #[serde(rename = "sampleValues")]
        sample_values: Vec<i64>,
    },
}
```

Generated TypeScript:

```typescript
export type DataElementSampleValueEntry = {
  dataElementId: string;
} & DataElementSampleValueVariant;
```

Generated Zod:

```typescript
export const DataElementSampleValueEntry$Schema: ZodType<DataElementSampleValueEntry> =
  z.strictObject({
    dataElementId: z.string(),
  }).and(z.lazy(() => DataElementSampleValueVariant$Schema)).meta({
    examples: []
  });
```

Notes:

- The flattened base joins the intersection under `z.lazy`. A base is a `const` of its own and nothing orders one type's schema against another's, so reading the name while the intersection's `const` initializes would fail for any base declared below -- and for two bases that flatten each other, no order puts each above the other. Deferred, every module loads whatever order it is assembled in, and a pair that does flatten each other fails when asked to validate rather than at import.
- Multiple `#[serde(flatten)]` fields chain: `{ ... } & BasePart & ExtraPart` in TypeScript and `z.strictObject({ ... }).and(z.lazy(() => BasePart$Schema)).and(z.lazy(() => ExtraPart$Schema))` in Zod.
- A struct whose only field is flattened becomes a plain alias (e.g. `export type FlattenOnly = DataElementSampleValueVariant;`).
- A flattened `ObjectId` joins its `$oid` key, which Serde writes among the object's own: `{"id":1,"$oid":"507f1f77bcf86cd799439011"}` for `#[model_schema(nonstrict)] pub struct Stamped { pub id: u32, #[serde(flatten)] pub oid: ObjectId }`. TypeScript and Zod intersect the object with the `$oid` object, and the JSON Schema adds `$oid` to the object's members, required. Serde reads `$oid` from every key still left and refuses no key beside it, so a holder of a flattened `ObjectId` is marked `nonstrict` ([Order and strictness of flattened members](#order-and-strictness-of-flattened-members)), and Zod and the JSON Schema read past a key none of its members reads, as Serde does. An `ObjectId` in the lone slot of a newtype variant under a `tag` with no `content` joins the tag's object the same way: Serde writes `{"kind":"Held","$oid":"507f1f77bcf86cd799439011"}` for `#[serde(tag = "kind")] pub enum Stamping { Held(ObjectId) }` and reads it back. TypeScript writes `{ kind: "Held"; } & ObjectId`, Zod intersects the tag's object with the `$oid` object, the JSON Schema adds `$oid` beside the tag, required, and the Dart, Swift and Kotlin types read the `ObjectId` from the object without the tag and write its `$oid` key beside the tag. The tag alone, `{"kind":"Held"}`, is refused as Serde refuses it: by Zod and the JSON Schema, and by TypeScript and each client where its `ObjectId` requires the `$oid` key. So is a key beside the tag and `$oid`, by Zod, the JSON Schema and each client's `ObjectId` as [the section on it](object-id.md#mongodb-objectid-support) declares it.
- **A type parameter is not flattened.** A `#[serde(flatten)]` member whose keys are those of one of the type's own parameters stops the build, on a struct and on a variant of an enum: the parameter itself, an `Option` or a `Box` of it, and a generic type that writes the parameter's keys at its own level, through a flattened member or an untagged variant that holds it. What fills the parameter is written in plain Rust, `serde_json::to_string(&Stamped::<Note> { .. })`, where no expansion reads it, and a filling that writes a key the holder already writes, or an `Option` of a type that reads `{}`, does not read back. A generic type that holds its parameter under a key of its own, `pub struct Page<T> { pub item: T }`, is flattened as any struct is. `pub struct Stamped<T> { pub created_at: String, #[serde(flatten)] pub record: T }` answers:

  ```text
  error: model_schema: type `Stamped` flattens `record` (`T`), whose keys are those of a type parameter: what fills it is written outside any `#[model_schema]` type, where nothing checks it, and a filling that writes a key `Stamped` already writes, or an `Option` of a type that reads `{}`, does not read back. Hold the member under a key of its own: remove `#[serde(flatten)]`
  ```

- **A map is flattened alone.** A `#[serde(flatten)]` member that writes a map, beside any other member that writes a key, stops the build, on a struct and on a variant of an enum under every tagging, in every build with `serde`: serde writes the map's entries at one level with that member's key, and no TypeScript type describes both. `{ note: string } & Partial<Record<string, number>>` refuses `{ note: "a", north: 2 }`, which serde reads. A map is written under a key of its own instead. A member that writes a map is a map, an `Option` of one and a `Box` of one, and a type declared above the holder that serde writes as one: a struct whose one member is a flattened map, a [brand](generics-and-brands.md#branded-newtypes) or a struct of one slot over a map, an alias of a map, and an `#[serde(untagged)]` enum with a variant that writes one. A generic type of those shapes over its own type parameter writes a map where a map fills that parameter. A member under `skip` writes no key and stands beside no map, and a variant under `#[serde(skip)]`, which serde neither writes nor reads, holds no map beside anything. A type declared below the holder, or in another crate, is not looked into: the expansion of the holder cannot see what it writes. `pub struct Stocktake { #[serde(flatten)] pub counts: BTreeMap<String, u8>, pub note: String }` answers:

  ```text
  error: model_schema: type `Stocktake`: field `counts`: `#[serde(flatten)]` cannot hold a map beside other members — serde writes the map's entries at one level with `note`, and no TypeScript type describes both. Write the map under a key of its own.
  ```

- **A map is not flattened beside a tag.** A `#[serde(flatten)]` member that writes a map, alone in a struct with its own `#[serde(tag = "...")]` or in a variant of an enum under a `tag` with no `content`, stops the build as well, in every build with `serde`: serde writes the tag and the map's entries at one level, and no TypeScript type describes both. `{ kind: "Open"; } & Partial<Record<string, number>>` refuses `{"kind":"Open","north":2}`, which serde reads. A struct's own tag is worse off still: serde hands it back to the map on a read, so it cannot read back a map of numbers it wrote, and it writes the tag twice for a map of text. A map is written under a key of its own instead, and in a variant a `content` key gives the map an object of its own. A variant written under its name, or untagged, writes no tag beside the map, and builds. A newtype variant under a tag alone whose value writes a map is refused the same way: see [Internally Tagged Enums](enums.md#internally-tagged-enums-tag-with-no-content). `#[serde(tag = "kind")] pub enum Keelson { Open { #[serde(flatten)] counts: BTreeMap<String, u8> } }` answers:

  ```text
  error: model_schema: type `Keelson`: variant `Open`, field `counts`: `#[serde(flatten)]` cannot hold a map beside the tag `kind` — serde writes the tag and the map's entries at one level, and no TypeScript type describes both. Write the map under a key of its own.
  ```

- **A map that reaches the member another way is refused as well**, in every build with `serde`. Each of these writes the map's entries at one level with `id`, and both TypeScript and Zod refuse what serde reads:
  - An untagged enum with a map among its variants, `#[serde(untagged)] pub enum Scores { Captioned(Captioned), Tallied(HashMap<String, i32>) }`, flattened in `pub struct Scoreboard { pub id: String, #[serde(flatten)] pub scores: Scores }`. An enum written under its variant's name or under a `content` key writes the map under a key of its own, and builds:

    ```text
    error: model_schema: type `Scoreboard`: field `scores`: `#[serde(flatten)]` cannot hold a map beside other members — serde writes the map's entries at one level with `id`, and no TypeScript type describes both. Write the map under a key of its own.
    ```

  - A generic type serde writes as its own argument, filled at a map: a brand `#[serde(transparent)] pub struct Wrap<T>(T);` in `pub struct Crate { #[serde(flatten)] pub body: Wrap<HashMap<String, i32>>, pub id: String }`, and in the same way an alias `type Held<T> = T;` and an untagged enum whose variant holds it. `Wrap<HashMap<String, i32>>` flattened alone builds:

    ```text
    error: model_schema: type `Crate`: field `body`: `#[serde(flatten)]` cannot hold a map beside other members — serde writes the map's entries at one level with `id`, and no TypeScript type describes both. Write the map under a key of its own.
    ```

  A generic type declared below the place that fills it, or in another crate, is not looked into: the expansion that fills it cannot see what it flattens.

- **A type parameter in the lone slot of a variant under a tag alone is not filled with an enum serde writes a variant of as an entry.** serde writes a unit variant of an externally tagged enum, and every variant of a plain enum, as an entry of its name over `null` where the enum is flattened or held by the lone slot of a variant under a tag alone: with `pub enum Pallet { Loose, Stacked { layers: u32 } }`, `#[serde(tag = "kind")] pub enum Waybill<Held> { Empty, Held(Held) }` writes `Waybill::Held(Pallet::Loose)` as `{"kind":"Held","Loose":null}`. The TypeScript type and the Zod schema of `Waybill` are written once for every filling, and describe `Held` as the type and the schema of what fills it, which describe the unit variant as its bare name, `"Loose"`. So a type parameter held by the lone slot of a variant under a tag alone stops the build where such a value fills it, in every build with `serde`: an externally tagged enum with a unit variant, under an `Option` or not, a brand or an alias over one, a plain enum, and an untagged enum with a member over one, declared above. It stops it where the map above does, and the error is spanned on the filling. Every other filling builds, an enum whose every variant holds a value among them; an `Option` held by the lone slot of a variant under a tag alone stops the build as the next point says. Named in place of the type parameter, an externally tagged enum is described by its entries on every surface. `pub struct Manifest { pub bill: Waybill<Pallet> }` answers:

  ```text
  error: model_schema: type `Manifest`: field `bill`: `Waybill` flattens its type parameter `Held` beside the tag `kind`, and `Pallet` fills it with a value serde writes a variant of there as an entry of its name over null — the TypeScript type and the Zod schema of `Waybill`, written once for every filling, describe that variant as its bare name. Name the enum where the type parameter stands, which every surface describes by its entries, or write it under a key of its own.
  ```

- **A type parameter in the lone slot of a variant under a tag alone is not filled with a value serde writes as no object.** serde refuses every write of text, a number, a `bool`, a list or a tuple flattened, and every write of one held by the lone slot of a variant under a tag alone, and writes `()` in either place as no key, or as the tag alone, where the TypeScript type and the Zod schema intersect the object with `null`: with `Waybill` above, `serde_json::to_string(&Waybill::Held("x".to_owned()))` answers `cannot serialize tagged newtype variant Waybill::Held containing a string`. serde refuses every write of an `Option` held by that slot, `Some` and `None` alike: `Waybill::Held(Some(Pallet::Loose))` answers `cannot serialize tagged newtype variant Waybill::Held containing an optional`. So a type parameter held by the lone slot of a variant under a tag alone stops the build where a value serde writes as no object fills it, as the same value held there stops it, in every build with `serde`: text, a number, a `bool`, a list, a tuple and `()`, and a brand, a struct of one slot or an alias over one, and an untagged enum with a member serde writes as one, declared above. It stops it as well where an `Option` fills it, or a struct of one slot or an alias declared above over one. It stops it where the map above does, a `default_types` entry among them, and the error is spanned on the filling. A struct and an enum serde writes as an object build. `pub struct Billed { pub bill: Waybill<Option<Pallet>> }` answers:

  ```text
  error: model_schema: type `Billed`: field `bill`: `Waybill` flattens its type parameter `Held` beside the tag `kind`, and `Option<Pallet>` fills it with a value serde writes as an optional, which cannot sit beside the tag: `#[serde(tag = "kind")]` with no `content` writes the variant's data as members of the object the tag is written in, and only a value serde writes as an object has members to put there. serde refuses every write of it at run time — `cannot serialize tagged newtype variant Waybill::Held containing an optional`. Write it under a key of its own.
  ```

- **A map keyed by a number or a `bool` is not read below a flattened member.** serde reads what a `#[serde(flatten)]` member holds with every key as text, and reads no number and no `bool` from text: `pub struct Soundings { #[serde(flatten)] pub rest: BTreeMap<isize, u8> }` writes `{"7":2}` and refuses it on the way back (`invalid type: string "7", expected isize`), and it refuses a struct flattened with such a map under a key of its own, at any depth, the same way; an `Option` of either reads it back as `None`. A `#[serde(flatten)]` member that holds such a map, at any depth, stops the build, on a struct and on a variant of an enum, in every build with `serde`, naming the member and the key: the map itself, under an `Option`, a list, a `Box` or another map's value, a type declared above that holds one (a struct, an enum, a [brand](generics-and-brands.md#branded-newtypes) or an alias), and a generic type filled at one. The key is a number or a `bool`, under `Box`, `Rc`, `Arc` or `Cow`, or a brand or an alias over one declared above, as for a type that [lists `"mongodb"`](mongodb-operations.md#mongodb-operations-and-typed-filters). A key that is one of the holder's own type parameters, a member serde does not read (`skip_deserializing`), a member its author reads through a `deserialize_with` or a `with` of their own, and a type declared below the holder are not refused. A map keyed by text, a `char`, a date or a plain enum is read from each key's text, and builds. `pub struct Soundings { #[serde(flatten)] pub rest: BTreeMap<isize, u8> }` answers:

  ```text
  error: model_schema: type `Soundings`: field `rest`: `#[serde(flatten)]` cannot hold a map keyed by `isize` — serde reads every key below a flattened member as text, and reads no number and no `bool` from text, so no entry of that map reads back. Key the map by a `String`, or write the field under a key of its own.
  ```

  A type parameter read below a flattened member is held to the same rule where it is filled: `pub struct Rows<T> { #[serde(flatten)] pub rest: BTreeMap<T, u8> }` reads `T` there as the key of a map. It builds, and the build stops where a number or a `bool` fills `Rows`: at any depth of a member, flattened or not (serde reads no entry of `Rows<u32>` wherever it reads one), in an alias, in a `default_types` entry of the type itself, and in a type that hands its own parameter on. The error is spanned on the filling. `pub struct Dock { pub rows: Rows<u32> }` answers:

  ```text
  error: model_schema: type `Dock`: field `rows`: `Rows` reads its type parameter `T` as the key of a map below `#[serde(flatten)]`, and `u32` fills it — serde reads every key below a flattened member as text, and reads no number and no `bool` from text, so no entry of that map reads back. Key the map by a `String`, or write the member under a key of its own.
  ```

- **A map keyed by a number or a `bool` is not read in an untagged enum, nor in an enum under a `tag` with no `content`.** serde reads such an enum from a copy of the payload it buffers, where every key is text, as it reads a flattened member: `#[serde(untagged)] pub enum Leadlines { Lines(BTreeMap<u32, u8>) }` writes `{"7":2}` and refuses it on the way back (`data did not match any variant of untagged enum Leadlines`), and `#[serde(tag = "kind")] pub enum Plumbed { Named { depths: BTreeMap<u32, u8> } }` writes `{"kind":"Named","depths":{"7":2}}` and refuses it (`invalid type: string "7", expected u32`). A member of a variant of such an enum that holds such a map stops the build, in every build with `serde`, naming the variant, the member and the key, with the reach of a flattened member: the map at any depth, a type declared above that holds one, a generic type filled at one, and a type parameter the enum reads there, where a number, a `bool` or a map keyed by one fills it. A key that is one of the enum's own type parameters, a member or a variant serde does not read (`skip_deserializing`), a member its author reads through a `deserialize_with` or a `with` of their own, and a type declared below the enum are not refused. An enum under its name and an enum under a `tag` and a `content` key build: serde reads the first with no copy, and the second where the tag comes ahead of the content, as serde writes it. `#[serde(untagged)] pub enum Leadlines { Lines(BTreeMap<u32, u8>) }` answers:

  ```text
  error: model_schema: type `Leadlines`: variant `Lines`, field `0`: an untagged enum cannot hold a map keyed by `u32` — serde reads an untagged enum from a copy of the payload it buffers, where every key is text, and reads no number and no `bool` from text, so no entry of that map reads back. Key the map by a `String`.
  ```

  and `#[serde(tag = "kind")] pub enum Plumbed { Named { depths: BTreeMap<u32, u8> } }` answers:

  ```text
  error: model_schema: type `Plumbed`: variant `Named`, field `depths`: an enum under a tag alone cannot hold a map keyed by `u32` — serde reads an enum under a tag alone from a copy of the payload it buffers, where every key is text, and reads no number and no `bool` from text, so no entry of that map reads back. Key the map by a `String`, or name a `content` key: serde writes the tag ahead of the content, and reads the content that follows it without a copy.
  ```

- A flattened map is handed every key of its object, so in **Zod** its record takes every key.
- In the **JSON Schema** a flattened map's values are the object's `additionalProperties`: `{"type": "object", "properties": {}, "required": [], "additionalProperties": {"type": "integer"}}` reads `{"north":2}` and refuses `"north": "x"`. A struct that flattens a map of its own, and an alias of a map, merge as the map does. A map keyed by a plain enum adds each of its members as an optional key, and every other key serde hands it is refused, as serde refuses it. A map keyed by a `char`, a date or a time, or by a type declared above that writes one, names the keys it reads by that key's own description, in `propertyNames`: `pub struct Ratlines { #[serde(flatten)] pub turns: BTreeMap<char, u8> }` is `{"type": "object", "properties": {}, "required": [], "additionalProperties": {"type": "integer"}, "propertyNames": {"type": "string", "minLength": 1, "maxLength": 1}}`, which reads `{"n":2}` and refuses `{"nn":2}`, as serde does, and a `NaiveDate` key is `{"type": "string", "format": "date"}`.
- **JSON Schema** stays strict: rather than `allOf` (which cannot faithfully compose a tagged union under `additionalProperties: false`), the base properties are distributed into each branch of the flattened union, keeping every branch closed. Both spellings of a union are distributed into: a discriminated enum's `oneOf` and an untagged enum's `anyOf`. Plain-struct flattens merge into a single closed object; multiple flattened unions form a cross-product.
- Each flattened union keeps the spelling it was written under. A discriminated enum's members are exclusive, so its branches stay a `oneOf`; an untagged enum is first-match-wins and its members may overlap (one member's keys a subset of another's, the difference optional), so its branches are an `anyOf` -- under `oneOf` the document would reject exactly what Serde writes for the narrower member, which matches both branches. An object flattening one of each nests the wrappers, the untagged `anyOf` sitting inside each branch of the discriminated `oneOf`.
- A flattened source reached through an `Option` is a choice rather than a key set. Serde writes its members beside the object's own for a `Some` and writes the object alone for a `None`, so the **JSON Schema** offers both under an `anyOf`: one branch with the source's members merged in, one naming the object's own keys alone. Folding the members into a single object would require keys the `None` payload never carries, and dropping them from `required` would admit a base written in part -- neither is a payload Serde produces. A union reached through an `Option` keeps its own spelling inside the branch and gains the absence outside it. Such a source takes no attribute that leaves a key out: `#[serde(flatten)] pub inner: Option<Inner>` builds, as serde writes nothing for its `None` and reads the payload back.
- In **TypeScript** the absence of a source reached through an `Option` closes the source's keys to `never`, but for those the object's own members and its other sources write, which a payload holds on either branch. A source that declares a key its holder or another source declares too is refused at expansion ([Order and strictness of flattened members](#order-and-strictness-of-flattened-members)).
- **An externally tagged enum is joined by the entry of each variant**, as serde writes it flattened: a variant that holds a value under its name, and a unit variant as its name over `null`, `{ "Calm": null; "Bay"?: never }` in TypeScript and `z.strictObject({ "Calm": z.null() })` in Zod, each closed to the other variants' names. A member that names a [`preprocess`](preprocess.md#preprocessing-preprocess) or a [`check`](checks.md#checks-check) is joined by the same entries, the functions written around them, so `{"note":"a","Calm":null}`, which serde writes, is read under a function too. An alias of the enum declared above is joined by the same entries, and so are a [brand](generics-and-brands.md#branded-newtypes) and a tuple struct of one slot over it, which serde flattens as the enum, and so is the enum held by a newtype variant under a `tag` with no `content`, which serde writes beside the tag as it writes it flattened ([Internally Tagged Enums](enums.md#internally-tagged-enums-tag-with-no-content)). An enum that declares a type parameter, written with an argument, is joined by its entries with the parameter written as the argument: `#[serde(flatten)] pub choice: Choice<u32>` over `pub enum Choice<Load> { Carried(Load), Empty }` is `({ "Carried": number; "Empty"?: never; } | { "Empty": null; "Carried"?: never; })` in TypeScript and `z.strictObject({ "Carried": z.number().int() })` and `z.strictObject({ "Empty": z.null() })` in Zod. An argument that is one of the holder's own type parameters is written as the holder declares it, and an alias that declares a type parameter of its own is filled the same way. A check is handed the enum's own value, a unit variant's bare name `"Calm"`, which is what its parameter's type names, and a check the enum names on itself is run on each entry the same way, as serde runs it on the value it read.
- **Zod** cannot name a choice as an operand, so it multiplies instead. An intersection recognizes exactly the keys its operands name; `z.discriminatedUnion` propagates its members' keys and is an operand like any other, while a plain `z.union` names none -- each of its branches would be asked to validate the whole payload alone and reject the keys the container and the sibling branches carry, which is every payload the object writes. So a flattened untagged enum, and a flattened source reached through an `Option`, are written as a union *of* intersections: one branch per combination, with the object's own keys bound once to `{Type}$OwnSchema` and read by every branch. A union nested inside a union contributes its leaves, the nesting writing no key of its own. With one combination there is nothing to choose between, so the object's own keys stay where they were. A check an untagged enum names is written on each member the holder joins, so the holder's Zod schema refuses what its `validate()` refuses, at the same path. An untagged enum that names a `preprocess`, or whose member is read as its default, publishes its members as `{Enum}$Members`, the `preprocess` written around each, and the holder joins `Holder$OwnSchema.and(z.lazy(() => {Enum}$Members[0]))` and one branch more per member: its own binding read beside the holder's keys refuses a payload that two members accept. An enum that declares a type parameter and is read that way is still joined by its binding. An untagged enum that declares a type parameter, written with an argument, is joined by its members with the parameter written as the argument: `#[serde(flatten)] pub either: Either<Crate>` beside `pub note: String` in `Flat`, over `#[serde(untagged)] pub enum Either<T> { Held(T), Counted { count: u32 } }`, is `Flat$OwnSchema.and(z.lazy(() => Crate$Schema))` and `Flat$OwnSchema.and(z.lazy(() => z.strictObject({ count: z.number().int(), })))`. In TypeScript the members of named fields are closed to each other's keys at the argument as well. An argument that is one of the holder's own type parameters is written as the holder declares it, and an alias that declares a type parameter of its own is filled the same way. An alias of the enum declared above is joined by the same members, in Zod and in TypeScript, where they are closed to each other's keys as the enum's own are: with `#[serde(untagged)] pub enum Skiff { Rowed { oars: u32 }, Sailed { sail: String } }` and `pub type SkiffAlias = Skiff;` declared above it, `#[serde(flatten)] pub skiff: SkiffAlias` beside `pub note: String` is `{ note: string; } & ({ oars: number; sail?: never } | { sail: string; oars?: never })`, which refuses `{"note":"n","oars":2,"sail":"s"}`, a payload serde never writes, as the Zod schema does.
- **An `Option` of a map is refused.** serde reads a flattened `Option` of a map as `Some` of a map of no entry from an object that holds no entry, so the `None` it writes as no key reads back as `Some`: `pub struct Locker { #[serde(default, flatten, skip_serializing_if = "Option::is_none")] pub counts: Option<BTreeMap<String, u8>> }` answers ``error: model_schema: type `Locker` flattens `counts` (`Option<BTreeMap<String, u8>>`): serde writes `None` as no key, and reads an object that holds no entry of `BTreeMap<String, u8>` as `Some` of a map of no entry. Flatten the map without the `Option`, which serde reads as a map of no entry where none is, or write `counts` under a key of its own.``. An `Option` of a struct whose every member is defaulted is refused the same way, with ``Give `Inked` a member serde requires``.
- **An `Option` of a struct or an enum is read as absent where its keys do not read.** serde reads a flattened `Option` of a struct or an enum as `None` wherever the keys it hands the source do not read as the source, and drops those keys with it, with no error. `pub struct Hawser { #[serde(default, flatten, skip_serializing_if = "Option::is_none")] pub burgee: Option<Burgee> }`, where `Burgee` is `pub struct Burgee { pub label: String }`, reads `{"label":"a"}` with `burgee: Some(Burgee { label: "a" })`, and `{"label":3}` with `burgee: None`, which it writes back as `{}`. TypeScript, **Zod** and the **JSON Schema** refuse `{"label":3}`: each offers the source's keys as the source reads them, or none of them. So a client that runs these checks cannot send a key that does not read, and a server that reads one from a client that does not run them loses it with no error.
- **Beside a `nonstrict` holder, an `Option` whose keys do not read is absent on every surface**, as serde reads it. #### Order and strictness of flattened members

serde reads a holder's `#[serde(flatten)]` members one at a time, in the order declared, from the keys the holder did not read itself. Some members take their own keys and remove them: a struct with no `#[serde(flatten)]` member and no tag of its own, an enum under no tag or under a tag and a content key, an `Option` of either, and a unit struct. Every other member reads every key still left and leaves it in place for the members after it: an enum under a tag alone, an untagged enum, a struct that flattens a member of its own or is under its own tag, an `ObjectId`, a member a `preprocess` reads, and a map. Such a member refuses a key it does not declare where it is strict, as `#[model_schema]` makes every type unless it is `nonstrict`: an enum under a tag alone or untagged with a struct variant, or with a newtype variant over a strict struct, and a closed struct of flattened members. Where it refuses one, it refuses the keys of the members beside it. A map reads them as its entries.

`#[model_schema]` builds only the shapes serde reads back, on the Rust read and on every other surface, and stops the build with the fix for the others:

| Flattened members | What the macro does |
|---|---|
| Every member takes its own keys | builds; the holder refuses a key no member declares, with a key of its own or none |
| One member that reads every key and refuses none, anywhere, or several, in a holder marked `nonstrict` | builds; the holder reads past a key no member declares |
| The same in a holder not marked `nonstrict`, where no member it flattens refuses a key it does not declare, and the member is neither a map nor read through a `preprocess` or a function of its author's | refused: mark the holder `nonstrict`, so every surface reads past such a key as serde does |
| One member that refuses a key it does not declare, declared after every other flattened member | builds; the holder reads past a key, and that member refuses one where it is strict |
| That member declared ahead of another | refused: declare it last |
| That member beside another member that reads every key, or beside the holder's own tag or a member serde writes and never reads | refused: mark it, and each strict struct a newtype variant of it holds, `nonstrict` |
| A map beside any other member | refused: write the map under a key of its own |
| A holder its author wrote `#[serde(deny_unknown_fields)]` on over a member that reads every key | refused: take the attribute off |
| Two members, or a member and the holder's own field, that write one key or one tag | refused: rename one of the keys, or write a member under a key of its own |
| A member that reads a key, under its name or an alias, that another member or the holder's own field writes, in either order | refused: rename the key, or write a member under a key of its own; where serde reads the key as the writer's, the Kotlin and Swift reads hand it to both |
| A member whose keys are those of a type parameter, the parameter or an `Option` of it among them | refused: what fills it is written where nothing checks it |
| A filling of a generic type, or a `default_types` entry, that breaks a rule above where the type reads its parameter as the key of a flattened map or in the lone slot of a variant under a tag alone | refused at the filling, where a `#[model_schema]` type or a `default_types` entry writes it |

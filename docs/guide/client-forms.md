### The Form Each Client Sends

Every client sends each value in the one form every target reads: serde, the Zod schema, the JSON Schema and each other client. A client writes a message through one codec on every transport, the TypeScript clients through the message's Zod check over HTTP, over the transport-agnostic seam and over the WebSocket transport, which carries that seam's messages. Two rules decide what is sent:

- **A value held in another form of the same value is sent in the form serde writes.** A `NaiveDateTime` handed as `2024-01-05T10:20:30.000Z`, the text JavaScript's `toISOString()` writes, is sent as `2024-01-05T10:20:30.000`: serde refuses the `Z` on a date and time with no zone, and the clock digits are kept. A `NaiveDateTime` or a `NaiveTime` with no seconds, `2024-01-05T10:20` or `10:20`, is sent with them, `2024-01-05T10:20:00` and `10:20:00`. A Dart `DateTime` is sent in UTC, through `toUtc().toIso8601String()`: `2026-10-22T17:07:11.032917Z`, where `toIso8601String()` alone writes no zone for a local `DateTime`, which serde refuses.
- **A value no form serde reads holds is refused before it is sent**: an integer outside its type's range, an `f32` beyond what a 32-bit float holds, an `f64` NaN, which serde writes as `null` and reads no more, a `char` of other than one code point, and a date or time text no rewrite turns into its form, `"hello"` or `"2024-01-05 10:20:30"`. A text in a form serde reads beside the one it writes is refused where Zod refuses it, `"2024-1-5"` for a `NaiveDate` among them.

| Type | Sent as | TypeScript | Dart | Swift | Kotlin |
|---|---|---|---|---|---|
| an integer | the integer, within the type's range | the Zod check refuses `256` for a `u8`: `z.number().int().min(0).max(255)` | `toJson` throws `FormatException: expected an integer from 0 to 255, found 256` | a `UInt8` holds no `256` | a `UByte` holds no `256` |
| `f32` | a number below `3.4028235677973366e38` in size, which serde reads as a finite `f32` | the Zod check reads `1e300` as `Infinity`, as serde reads it, and the client refuses it before it is sent: `expected a 32-bit float, found Infinity` | `FormatException: expected a 32-bit float, found 1e+300` | a `Float` holds no `1e300` | a `Float` holds no `1e300` |
| `char` | one code point | `z.string().length(1)` refuses `"ab"` | `FormatException: expected a character, found "ab"` | `EncodingError.invalidValue`: `expected a character, found "ab"` | `SerializationException: expected a character, found "ab"` |
| `NaiveDate` | `2024-01-05` | `z.iso.date()` refuses `"2024-1-5"` | `FormatException: expected a date, found "2024-1-5"` | `EncodingError.invalidValue`: `expected a date, found "2024-1-5"` | `SerializationException: expected a date, found "2024-1-5"` |
| `NaiveTime` | `10:20:30`, a fraction kept, and `10:20` as `10:20:00` | the schema's preprocessor rewrites | `toJson` rewrites | `encode(to:)` rewrites | the serializer rewrites |
| `NaiveDateTime` | `2024-01-05T10:20:30`, a fraction kept, a `Z` dropped, and `T10:20` as `T10:20:00` | the schema's preprocessor rewrites | `toJson` rewrites | `encode(to:)` rewrites | the serializer rewrites |
| `DateTime<Tz>` | RFC 3339 with its zone | a `Date`, which `JSON.stringify` writes `2024-01-05T10:20:30.000Z` | `toUtc().toIso8601String()`, `.000Z` written as `Z` | a `Date`, written with a fraction of milliseconds where it has one: `2024-01-05T10:20:30Z`, `2024-01-05T10:20:30.500Z` | the text, held to RFC 3339 with its zone, and `T10:20Z` as `T10:20:00Z` |
| `DateTime<Tz>` under `as_number` | the integer of epoch milliseconds | `z.number().int()` refuses `1.5` | an `int` | an `Int64` | a `Long` |

A value already in that form is sent as it is, so no payload a client sent before changes. A map's key is sent in the form its value is, but a `DateTime<Tz>` key in TypeScript, a string the Zod schema holds to RFC 3339 with its zone and sends as it is. A `literal = 214` on an integer field is held in the field's own integer type, and written `214`. The rules hold for every value a client writes: the message, on every transport, and a value it writes as text into a path, a query, a header or a part, which is the text of the form the Rust dispatcher reads -- a number, a `bool`, a `char`, a date and a time as their form writes them, a plain enum as its name, a list joined with `,` -- and is refused before anything is sent where no form holds it, as the client refuses a message: the TypeScript and Swift clients answer the fault, and the Dart and Kotlin clients throw. A `DateTime<Tz>` the TypeScript client writes as text is the JavaScript `Date` its Zod schema reads the value into, written by `toISOString()`, so a text handed with no zone is read in the zone the program runs in. A header is refused as well where its text holds a character no HTTP header holds. The Dart and Kotlin `ws_rpc` dispatcher attachments hold what a handler answers to the same forms: a reply, a declared error or a `header_out` no form holds is answered as a `handler-panic` fault, the one a handler that threw is answered with. An `f32` or an `f64` there that is not finite, which serde writes as `null`, is written as `null`, as the Rust and TypeScript dispatchers write it: a message that holds `1e39` for an `f32` is read as an infinity and handed back as `"ring": null`.

What a client cannot hold is left as it is:

- **An integer a JavaScript `number` does not hold exactly**: an `isize` or a `usize` beyond `2^53 - 1` in size, and an `i64` or a `u64` as a map's key. serde writes `1152921504606846976`, `JSON.parse` reads `9007199254740993` as `9007199254740992`, and `z.number().int()` refuses any integer beyond `Number.MAX_SAFE_INTEGER`, `1152921504606846976` among them. Dart, on the Dart VM, Swift and Kotlin send it as it is, and a build with `swift` or `kotlin` refuses `u64` and `usize`. Every other `i64` and `u64` is a `bigint` in TypeScript, which the client sends as the JSON number of its digits (see [A `u64` and an `i64` are a `bigint` in TypeScript](models.md#a-u64-and-an-i64-are-a-bigint-in-typescript)).
- **A year outside 0000 to 9999 and a leap second.**

`tests/wire_forms_tests/models.rs` holds the table, `WIRE_FORMS`: each value a caller hands a client, what serde answers of it, and what each client sends of it, or that it refuses it. Each client's run sends every row through its own codec, serde reads every payload any client sends, and the Zod schema and the JSON Schema read each one.

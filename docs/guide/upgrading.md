Read the entries through `.held.storage`. A map keyed by a `String` keeps its text.
- **The Swift client reads an alias of a map under a key it wraps, and an alias of a `DateTime<Tz>`, as serde writes them**: `pub type Numbering<Stowed> = HashMap<u32, Stowed>;` is `NumberingType<Stowed> = NumberingTypeKeyedMap<Stowed>`, and `pub type Moonrise = DateTime<Utc>;` is `MoonriseType = MoonriseTypeDate`, a struct of one `value`, where each was the Swift type itself and read an array and a number. A field typed with the alias holds that struct, and an alias of a map keyed by a `String` keeps its text. The `storage` of each map wrapper and its `init(storage:)` are `public`, so a client can build and read one.
- **The Swift client keeps a map's entry whose value is `null`** under a key it wraps and, where `validate()` walks the value, under a key it keys natively: `{"1":null}` read as `HashMap<u32, Option<DateTime<Utc>>>` holds the key `1` with `nil` and writes `{"1":null}`, where the entry was dropped.
- **A named type used two or more times in one JSON Schema document is written once under `$defs` and referenced with `$ref` at each use**, in `json_schema()`, in each tool's `inputSchema` and `outputSchema` and in the `components.schemas` of `openapi()`, where it was written in full at each use and only a recursive type was a definition. With `pub struct UserWithAddress { pub address: Address, pub backup_addresses: Vec<Address> }`, `json_schema()["properties"]["address"]` is `{"$ref": "#/$defs/Address"}` where it was the object `Address` describes; a brand over a `String` used twice is `{"$ref": "#/$defs/UserId"}` where it was `{"type": "string"}`. A type used once is written in place, as it was. A second type published under a name another type's definition holds, with another body, is defined under the name followed by a fingerprint of its body, `Revision.a38e709c45a1e062`. A generic type filled with a named type is keyed by that type's name, `Page.User-<fingerprint>` where it was `Page.object-<fingerprint>`. Code that reads a member's schema out of a document reads it through the definition its `$ref` points at. See [Nested Types](nested-recursive-and-aliased-types.md#nested-types).
- **The `jsonschema` feature is gone: a type asks for its JSON Schema with `enable = ["jsonschema"]`.** A manifest that writes `features = ["jsonschema"]` stops at resolution, ``package `inventory` depends on `tixschema` with feature `jsonschema` but `tixschema` does not have that feature.`` Drop the feature, and list the entry on each type whose `json_schema()` you call: a type without it has none, ``error[E0599]: no associated function or constant named `json_schema` found for struct `Address` in the current scope``. Every model type such a type holds lists the entry too, or the build stops at the holder with ``error[E0599]: no associated function or constant named `json_schema_within` found for struct `address_schema::Schema` in the current scope``. See [JSON Schema Method Missing](troubleshooting.md#json-schema-method-missing).
- **Without tixschema's `serde` feature, TypeScript and Zod write each member in camelCase**, where TypeScript wrote it as Rust names it: `pub user_id: String` is `userId: string` where it was `user_id: string`. No `#[serde(...)]` attribute is read in that build, so `#[serde(rename = "mail")] pub email_address: String` is `emailAddress`, where serde writes `mail`. Turn the feature on, as the default `web` set does, for the names serde writes. See [Serde Attribute Support](serde-attributes.md#serde-attribute-support).
- **A brand needs tixschema's `serde` feature.** Without it `#[serde(transparent)]` is not read, so `pub struct UserId(pub String);` under it is `export type UserId = string;`, where it was `string & { readonly [__brand_UserId]: true }`, and its Zod schema is `z.string()`. A `pattern`, `minLength` or `maxLength` on the struct stops the build: ``error: model_schema: type `Username`: `minLength` is supported only on a branded newtype: a `#[serde(transparent)]` struct serde writes as the value of one field. A branded newtype is read with tixschema's `serde` feature, which this build has off. On a field, write it in `#[model_schema_prop(...)]`.`` See [Branded Newtypes](generics-and-brands.md#branded-newtypes).
- **A crate that invokes a service's dispatcher, client or server macro lists `serde_path_to_error`**: the readers each of them emits name the path of a value serde refuses through it. Without it the build stops at each macro the crate invokes, ``error[E0433]: cannot find `serde_path_to_error` in the list of imported crates``. Add `serde_path_to_error = "0.1"` to its `[dependencies]`. See [The `amqp_rpc` walkthrough](services.md#the-amqp_rpc-walkthrough).

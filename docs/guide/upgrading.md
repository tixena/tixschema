#### What an upgrade asks of your crate

Seventy-six rules meet a crate that upgrades. Each is stated with what a build or a read answers:

- **The Dart, Kotlin and Swift reads of a strict struct that flattens a member declared below it, or in another crate, refuse a key no member declares**, as serde does, where they read past it.
- **A `nonstrict` struct that flattens a member, or enum with a variant, that refuses a key no member declares refuses it on every surface**, as serde does, where Zod, the JSON Schema, Kotlin and Swift read past it. See [Unknown Keys](models.md#unknown-keys-strict-reads-and-nonstrict).
- **A strict struct that flattens a generic type declared below it, or in another crate, warns in a build with Dart, Kotlin or Swift on**, where it built in silence: those reads read past a key no member declares, which the Rust read refuses, and a crate built with `-D warnings` stops there. See [Unknown Keys](models.md#unknown-keys-strict-reads-and-nonstrict).
- **A variant of an untagged enum every value of which an earlier variant reads stops the build**, where it built and never read back. See [Untagged Enums](untagged-enums.md#untagged-enums-serdeuntagged).
- **A member type written with its path reaches its schema module through that path**: `invoice_lookups::DropOff` reads `invoice_lookups::drop_off_schema`, where the build stopped with `E0433` unless the module was imported. See [A Model Type Declared in Another Module](troubleshooting.md#a-model-type-declared-in-another-module).
- **A struct under a tag of its own that is not `nonstrict` stops the build**, where serde read past a key no member declares and Zod, the JSON Schema and the Kotlin read refused it: serde cannot refuse one beside the tag, as `#[serde(deny_unknown_fields)]` there refuses the tag itself. Mark the struct `#[model_schema(nonstrict)]`, and every surface reads past such a key; a holder that flattens it reads past one too, in Kotlin as in serde.
- **The Swift read of a flattened strict untagged enum takes the variant serde takes**, where it took an earlier variant that read from an object of none of its keys and dropped the keys of the right one: with a variant of optional members ahead of `Painted { colour: String }`, untagged and flattened beside `label`, `{"colour":"red","label":"f2"}` reads as `Painted`, where Swift read it as the first.
- **The Swift read refuses a key no member declares beside a flattened enum, a flattened struct of one slot, and a flattened member that reads every key left and refuses one**, as serde refuses it, where it read past it; the Kotlin read refuses it beside a flattened struct of one slot as well. With `pub struct Carton { pub label: String, #[serde(flatten)] pub size: Size }` and `pub enum Size { Large(Weight), Small { width: u32 } }`, `{"label":"c1","Small":{"width":3},"stray":1}` is refused.
- **The Kotlin read refuses a key no member declares beside a flattened member that reads every key left and refuses one**, as serde refuses it, where it read past it: with `pub struct Customer { pub name: String, #[serde(flatten)] pub contact: Contact }` and `pub struct Contact { pub phone: String, #[serde(flatten)] pub address: Address }`, `{"name":"Ana","phone":"555","city":"Lima","stray":1}` is refused (`Encountered an unknown key 'stray'`). The same holds for a strict enum under a tag alone and a strict untagged enum, flattened.
- **A flattened member whose keys tixschema cannot see stops the build beside another key**, where it built and a key of its could collide with the key beside it: `pub struct Customer { pub name: String, #[serde(flatten)] pub address: Address }` with `Address` a plain serde struct, or a plain alias of a map. Give the type `#[model_schema()]` and declare it above, or write the member under a key of its own. A hint that moves a flattened `Option` with no `skip_serializing_if` under a key of its own now names `#[serde(default, skip_serializing_if = "Option::is_none")]`, which `#[model_schema]` asks of an `Option` member there.
- **A member that reads a key under an alias that another member or the holder's own field writes stops the build in either order**, where it built with the writer first: `pub struct Order { pub label: String, #[serde(flatten)] pub price: Price, #[serde(flatten)] pub discount: Discount }`, with `Price { amount: u32 }` and `Discount { #[serde(alias = "amount")] percent: u32 }`, read back in Rust and was refused by the Kotlin and Swift reads (`duplicate field`). Rename the key, or write a member under a key of its own; the hint no longer says to reorder.
- **A `#[serde(flatten)]` member whose keys are those of a type parameter stops the build**, where it built and a filling that wrote a key of the holder's, or an `Option` of a type that reads `{}`, did not read back: `pub struct Stamped<T> { pub created_at: String, #[serde(flatten)] pub record: T }` filled at `Note { created_at: String, text: String }` wrote `created_at` twice and refused it on the way back (``duplicate field `created_at` ``). Hold the member under a key of its own; a generic type that holds its parameter under a key, `Page<T> { item: T }`, is flattened as before.
- **A key no member declares is refused by the Rust read**, on every struct of named members and every enum `#[model_schema]` expands, and on every message the `service_schema` macros generate, where serde read past it and dropped the value: a caller that sends `{"name":"a","stray":1}` to a `Role` is refused with `unknown field `stray``, and a dispatcher answers `failed-validation` and calls no handler. Opt a type out with [`#[model_schema(nonstrict)]`](models.md#unknown-keys-strict-reads-and-nonstrict), which reads past the key on every surface; Zod writes `z.object` and the JSON Schema `"additionalProperties": true` for it. A type that flattens a member serde reads every key for, or one whose kind the expansion cannot see, and one under its own `tag`, is not closed; a type whose flattened members all take their own keys is, with a key of its own or none, and so are a braced struct of no member and the message of an operation of no argument, which answers `{"stray":1}` with `failed-validation` and the field `stray`.
- **A flattened member serde would not read back where it is declared, or as strict as it is, stops the build**, on a struct and on a variant of an enum, naming the fix: a member that reads every key still left and refuses one it does not declare, a strict enum under a tag alone or untagged among them, declared ahead of another flattened member (``Declare `shape` after every other flattened member.``), beside another member that reads every key or beside its holder's own tag (``Mark `Shape` and `Lid` `#[model_schema(nonstrict)]`.``), a holder written `#[serde(deny_unknown_fields)]` over such a member, two members, or a member and a field of the holder's own, that write one key or one tag (``Rename the key in one of them, or write `stamp` under a key of its own.``), a member that reads a key a member after it writes, and a type parameter flattened ahead of another member or beside one that reads every key. A filling of a generic type that flattens its parameter, and a `default_types` entry, are held to the same rules where they are written. A member declared below its holder or in another crate is held to the same rules by a `const` the compiler evaluates, `error[E0080]: evaluation panicked: model_schema: ...`, a key it declares that another source of keys of the holder declares among them, and a type no `#[model_schema]` expanded is read as the strictest member. Reorder, mark nonstrict or rename as the error says. See [Order and strictness of flattened members](flatten.md#order-and-strictness-of-flattened-members).
- **A holder whose flattened members all take their own keys refuses a key none declares, a member declared below it or in another crate counted among them**, where it read past such a key: with `struct Overcast { note: String, #[serde(flatten)] stratus: Hazing }` declared above `enum Hazing { Bay { label: String } }`, `{"note":"a","Bay":{"label":"n"},"north":2}` is refused with ``unknown field `north` ``. Where the member declared below reads every key still left, the build stops: ``Mark `Shipment` `#[model_schema(nonstrict)]` ``. A member through an `Option` or an alias declared below it is read at its strictest, so its holder is marked `nonstrict`.
- **A flattened `Option` that serde reads back as `Some` from an object that holds none of its keys stops the build**, an `Option` of a map among them (``Flatten the map without the `Option` ``) and an `Option` of a struct whose every member is defaulted, and so does a variant of an untagged enum that reads every object declared ahead of one serde writes as an object (``Declare `Any` after every other variant.``). A member declared below its holder that serde writes as no object, or that is an externally tagged enum with a unit variant, stops it too, by the `const` beside the holder. With Dart or Swift on, a member that refuses a key flattened after one declared below its holder, and a member beside another key whose type holds a type declared below that type, stop it: ``Declare `Hue` above `Parcel` ``.
- **The Dart read of a struct under its own tag reads past a key no member declares**, as serde reads it, where it refused one: `{"kind":"TaggedMobile","name":"x","stray":1}` reads. A member flattened beside others is handed the object without its holder's own keys and those the members ahead of it took, as serde hands it. The numbered helpers the Kotlin and Dart emitters declare carry the crate's name after their number, `KotlinNumber1KotlinTests`, so two crates' definitions compile in one package.
- **The unit variant of a strict enum under a tag alone refuses a key beside the tag**, on the Rust, Dart and Swift reads, where the Rust read and the Dart and Swift reads of an enum whose variants hold a struct declared below it read past it: `#[serde(tag = "kind")] pub enum Tide { Ebbing { height: u32 }, Slack }` refuses `{"kind":"Slack","stray":1}` with ``unknown field `stray`, there are no fields``. Mark the enum `nonstrict` to read past it.
- **A flattened `Option` of a type that reads every key still left and refuses one it does not declare stops the build**, where serde read the `Option` as `None` beside a key no member declares: with `#[serde(tag = "kind")] pub enum Mark { Line { length: u32 } }`, `pub struct Parcel { pub label: String, #[serde(flatten, default, skip_serializing_if = "Option::is_none")] pub mark: Option<Mark> }` answers ``Mark `Mark` `#[model_schema(nonstrict)]`, flatten `Mark` without the `Option`, or write `mark` under a key of its own.``
- **An enum a variant of which flattens a member that reads every key still left stops the build where another of its levels would refuse a key**, the object under a tag and a content key, another struct variant or a unit variant under a tag alone, as serde reads `deny_unknown_fields` for every variant at once: ``Mark `Label` `#[model_schema(nonstrict)]`, or hold the members of `Marked` in a struct of their own and write `Marked` as a newtype variant over it.``
- **A member declared below its holder or in another crate that declares a key another source of keys of the holder declares stops the build**, naming the key, through the constant `__TIXSCHEMA_KEYS` every type publishes, and so does one that is a plain enum, a map beside another key, a type that holds a map keyed by a number or a `bool` (at any depth, and in a member of a variant of an enum under a tag alone or untagged), or a type serde writes as an `Option` whose `None` reads back as `Some`, and a newtype variant under a tag alone over a type declared below it that serde writes as no object. Each of these declared above was refused already.
- **The Swift read of a flattened type parameter is handed the object as serde hands it**, through `SwiftSchemaPayload.read`, where it read the holder's whole decoder: `Wrap<Ink>` flattened beside a field `code` reads `{"code":"c","hue":"red","depth":2}`, which a strict `Ink` refused with ``unknown field `code` ``.
- **A map under `#[serde(flatten)]` beside another member that writes a key stops the build**, on a struct and on a variant of an enum: `pub struct Stocktake { #[serde(flatten)] pub counts: BTreeMap<String, u8>, pub note: String }` answers ``error: model_schema: type `Stocktake`: field `counts`: `#[serde(flatten)]` cannot hold a map beside other members — serde writes the map's entries at one level with `note`, and no TypeScript type describes both. Write the map under a key of its own.`` Write the map under a key of its own, `pub counts: BTreeMap<String, u8>`. See [Intersection Types](flatten.md#intersection-types-serdeflatten).
- **A map keyed by a number or a `bool` below a `#[serde(flatten)]` member stops the build**, at any depth, on a struct and on a variant of an enum, as does a type declared above that holds one there, and a type parameter read there filled with a number, a `bool` or a map keyed by one: serde reads no entry of such a map back. `pub struct Soundings { #[serde(flatten)] pub rest: BTreeMap<isize, u8> }` answers ``error: model_schema: type `Soundings`: field `rest`: `#[serde(flatten)]` cannot hold a map keyed by `isize` — serde reads every key below a flattened member as text, and reads no number and no `bool` from text, so no entry of that map reads back. Key the map by a `String`, or write the field under a key of its own.`` Key the map by a `String`, or write it under a key of its own, `pub rest: BTreeMap<isize, u8>`. See [Intersection Types](flatten.md#intersection-types-serdeflatten).
- **A map keyed by a number or a `bool` in an untagged enum, or in an enum under a `tag` with no `content`, stops the build**, at any depth of a member of a variant, as does a type declared above that holds one there, and a type parameter read there filled with a number, a `bool` or a map keyed by one: serde reads such an enum from a copy of the payload it buffers, and reads no entry of such a map back. `#[serde(untagged)] pub enum Leadlines { Lines(BTreeMap<u32, u8>) }` answers ``error: model_schema: type `Leadlines`: variant `Lines`, field `0`: an untagged enum cannot hold a map keyed by `u32` — serde reads an untagged enum from a copy of the payload it buffers, where every key is text, and reads no number and no `bool` from text, so no entry of that map reads back. Key the map by a `String`.`` Key the map by a `String`, or, in an enum under a `tag`, name a `content` key. See [Intersection Types](flatten.md#intersection-types-serdeflatten).
- **A map keyed by a `char`, a date, a number or a `bool` describes its values in the JSON Schema**, at every position, and names its keys by the text serde writes them as, in `propertyNames`: `HashMap<u32, u8>` is `{"type": "object", "additionalProperties": {"type": "integer"}, "propertyNames": {"type": "string", "pattern": "^-?[0-9]+(\\.0+)?$"}}`, where it was `{"type": "object", "additionalProperties": true}`, and refuses `{"7": "x"}`, as serde and Zod refuse it. A tuple as a map's value is described as the fixed array it is anywhere else, where the build stopped (`a tuple is not supported as a map value`), and a [brand](generics-and-brands.md#branded-newtypes) over a `char` as `{"type": "string", "minLength": 1, "maxLength": 1}`, where it was `{"type": "string"}`. See [Collections and Maps](models.md#collections-and-maps).
- **A map under `#[serde(flatten)]` alone beside a tag stops the build**, in a struct with its own `#[serde(tag = "...")]` and in a variant of an enum under a `tag` with no `content`: `#[serde(tag = "kind")] pub enum Keelson { Open { #[serde(flatten)] counts: BTreeMap<String, u8> } }` answers ``error: model_schema: type `Keelson`: variant `Open`, field `counts`: `#[serde(flatten)]` cannot hold a map beside the tag `kind` — serde writes the tag and the map's entries at one level, and no TypeScript type describes both. Write the map under a key of its own.`` Write the map under a key of its own, or, in a variant, name a `content` key. See [Intersection Types](flatten.md#intersection-types-serdeflatten).
- **A newtype variant under a `tag` with no `content` whose value writes a map stops the build**: a struct whose one member is a flattened map, a brand or a struct of one slot over a map, an alias of a map and an untagged enum with a variant that writes one, declared above the enum. With `pub struct Tally { #[serde(flatten)] counts: BTreeMap<String, u8> }`, `#[serde(tag = "kind")] pub enum Filled { Counted(Tally) }` answers ``error: model_schema: type `Filled`: variant `Counted`, field `0`: `Tally` writes a map, which cannot sit beside the tag `kind` — serde writes the tag and the map's entries at one level, and no TypeScript type describes both. Name a `content` key so the map gets an object of its own, or write the map under a key of its own.`` A variant that holds the enum's own type parameter is refused where a map fills it. Name a `content` key, or write the map under a key of its own. See [Internally Tagged Enums](enums.md#internally-tagged-enums-tag-with-no-content).
- **A map that reaches a flattened member through an untagged enum, a generic type or a type parameter stops the build** beside another member that writes a key, as a map written there does: an `#[serde(untagged)]` enum with a map among its variants, and a brand, an alias or a struct over its own type parameter filled at a map, are refused with the error of a map written there, and a type parameter flattened beside a member is refused where a map fills it: with `Letter<T>` flattening `T` beside `id`, `pub struct Post { pub letter: Letter<HashMap<String, i32>> }` answers ``error: model_schema: type `Post`: field `letter`: `Letter` flattens its type parameter `T` beside `id`, and `HashMap<String, i32>` fills it with a map — serde writes the map's entries at one level with `id`, and no TypeScript type describes both. Write the map under a key of its own.`` Write the map under a key of its own. See [Intersection Types](flatten.md#intersection-types-serdeflatten).
- **A type parameter held by the lone slot of a variant under a tag alone stops the build where an enum serde writes a variant of as an entry fills it**: an externally tagged enum with a unit variant, a plain enum, and an untagged enum with a member over one, declared above. With `pub enum Pallet { Loose, Stacked { layers: u32 } }` and `#[serde(tag = "kind")] pub enum Waybill<Held> { Empty, Held(Held) }`, `pub struct Manifest { pub bill: Waybill<Pallet> }` answers ``error: model_schema: type `Manifest`: field `bill`: `Waybill` flattens its type parameter `Held` beside the tag `kind`, and `Pallet` fills it with a value serde writes a variant of there as an entry of its name over null — the TypeScript type and the Zod schema of `Waybill`, written once for every filling, describe that variant as its bare name. Name the enum where the type parameter stands, which every surface describes by its entries, or write it under a key of its own.`` See [Intersection Types](flatten.md#intersection-types-serdeflatten).
- **An externally tagged enum that declares a type parameter, written with an argument and flattened or held by the lone slot of a variant under a tag alone, is described by its entries**, each written at the argument, where a flattened one named the enum's own unbound parameter, and one beside a tag was joined as the enum's own type and schema, which refused a unit variant's entry over `null`. See [Intersection Types](flatten.md#intersection-types-serdeflatten).
- **A type parameter held by the lone slot of a variant under a tag alone stops the build where a value serde writes as no object fills it**, as the same value held there does: text, a number, a `bool`, a list, a tuple, `()`, and a brand, a struct of one slot, an alias or an untagged enum declared above that serde writes as one, at any depth of a member, in an alias and in a `default_types` entry; it stops it where an `Option` fills it, of which serde refuses every write there. With `Pallet` and `Waybill` above, `pub struct Billed { pub bill: Waybill<Option<Pallet>> }` answers ``error: model_schema: type `Billed`: field `bill`: `Waybill` flattens its type parameter `Held` beside the tag `kind`, and `Option<Pallet>` fills it with a value serde writes as an optional, which cannot sit beside the tag: `#[serde(tag = "kind")]` with no `content` writes the variant's data as members of the object the tag is written in, and only a value serde writes as an object has members to put there. serde refuses every write of it at run time — `cannot serialize tagged newtype variant Waybill::Held containing an optional`. Write it under a key of its own.`` Fill the parameter with a type serde writes as an object, or write the value under a key of its own. See [Intersection Types](flatten.md#intersection-types-serdeflatten).
- **An untagged enum that declares a type parameter, written with an argument and flattened, is described by its members**, each written at the argument, where its Zod schema named the enum's own factory argument, which nothing in the holder binds, and threw `ReferenceError` as it parsed. See [Intersection Types](flatten.md#intersection-types-serdeflatten).
- **An alias of an untagged enum, flattened, is described in TypeScript by the enum's members**, each closed to the others' keys, with a type parameter of its own or with none, where it was described by its name: with `#[serde(untagged)] pub enum Skiff { Rowed { oars: u32 }, Sailed { sail: String } }` and `pub type SkiffAlias = Skiff;`, a value of the type of `pub struct Dinghy { pub note: String, #[serde(flatten)] pub skiff: SkiffAlias }` that holds the keys of both members, `{ note: "n", oars: 2, sail: "s" }`, which `tsc --strict` took and the Zod schema refuses, answers ``error TS2322: Type '{ note: string; oars: number; sail: string; }' is not assignable to type 'Dinghy'.`` See [Intersection Types](flatten.md#intersection-types-serdeflatten).
- **A newtype variant under a `tag` with no `content` that wraps a `HashSet`, a `BTreeSet`, a `VecDeque`, a `BinaryHeap` or an `IndexSet` stops the build with the refusal of a sequence**, as one that wraps a `Vec` does, where it stopped it with ``error[E0433]: cannot find module or crate `hash_set_schema` in this scope``: `#[serde(tag = "kind")] pub enum Tagged { Held(HashSet<u32>) }` answers ``error: model_schema: variant `Held` of internally tagged enum `Tagged` wraps a sequence, which cannot sit beside the tag: ...``, quoting serde's `cannot serialize tagged newtype variant Tagged::Held containing a sequence`. See [Internally Tagged Enums](enums.md#internally-tagged-enums-tag-with-no-content).
- **A member that holds `serde_json::Value` or `serde_json::Map` stops the build**, at any depth: a `pub v: serde_json::Value` on `Holding` answers ``error: model_schema: type `Holding`: field `v` reaches `serde_json::Value`, which holds any JSON value, so no target can describe it. Declare the shape that value takes as a type of its own, and write that type in its place.`` A bare `Value` or `Map<K, V>` that names `serde_json`'s type stops it at a check the compiler evaluates beside the item, with `error[E0080]: evaluation panicked:` and the same message, and a crate that writes either bare name in a member lists `serde_json` among its dependencies, which the check names. A service operation whose message, reply, fault, header or part reaches one stops the build too, the error naming the operation and the position. See [A JSON value is no member](models.md#a-json-value-is-no-member).
- **A `u64` and an `i64` are a `bigint` in TypeScript**, where they were a `number`: `pub signed: i64` is `signed: bigint`, so a value written with a `number` there, `{ signed: -7 }`, answers ``error TS2322: Type 'number' is not assignable to type 'bigint'.`` Write `-7n`. The Zod schema reads a `bigint`, and a `number` that holds the integer exactly, and answers the `bigint`, through `z.codec`. `literal = 214` on an `i64` is `214n` in TypeScript. The wire does not change: serde writes the number, and the JSON Schema and the Dart, Swift and Kotlin types are what they were. The TypeScript service code reads each JSON text with a reviver that keeps an integer beyond `2^53 - 1` exact, and writes each `bigint` through `JSON.rawJSON`; a transport of the transport-agnostic client and dispatcher reads its text the same way to keep such an integer. See [A `u64` and an `i64` are a `bigint` in TypeScript](models.md#a-u64-and-an-i64-are-a-bigint-in-typescript).
- **A `Vec<u8>` is a `Uint8Array` in TypeScript and a `Uint8List` in Dart**, where it was an `Array<number>` and a `List<int>`: `pub data: Vec<u8>` is `data: Uint8Array`, so a literal array there, `{ data: [1, 2] }`, answers ``error TS2740: Type 'number[]' is missing the following properties from type 'Uint8Array<ArrayBufferLike>'.`` Write `Uint8Array.from([1, 2])`. `Array.isArray` answers `false` for a `Uint8Array`, which has no `push`, `splice` or `concat`, and whose `.map` answers a `Uint8Array`: `new Uint8Array([1, 2]).map((v) => `#${v}`)` is `[0, 0]`. `JSON.stringify` writes a `Uint8Array` as an object, so encode with the schema, or write through the emitted service code, before you hand a value to it. In Dart a `Uint8List` is a `List<int>`, so code that reads it keeps working; code that builds one writes `Uint8List.fromList([1, 2])`, and the file that holds the generated types imports `dart:typed_data`. See [A `Vec<u8>` is a `Uint8Array` in TypeScript and a `Uint8List` in Dart](models.md#a-vecu8-is-a-uint8array-in-typescript-and-a-uint8list-in-dart).
- **A member that holds an `i128`, a `u128`, an `f16` or an `f128` stops the build with a refusal that names it**, at any depth, where it stopped it with ``error[E0433]: cannot find module or crate `i128_schema` in this scope``: `pub struct FieldWide { pub x: i128 }` answers ``error: model_schema: type `FieldWide`: field `x` reaches `i128`, which no surface describes: no TypeScript, Zod, JSON Schema, Dart, Swift or Kotlin type is written for it. Hold the value as an `i64` or a `u64`, or as a `#[model_schema]` brand over `String` that carries its digits.`` See [`i128`, `u128`, `f16` and `f128` are no member](models.md#i128-u128-f16-and-f128-are-no-member).
- **A plain enum under `#[serde(flatten)]` stops the build with `serde` and no schema surface**, as it stops one with a surface: a build of the Dart, Swift and Kotlin clients alone took it, and no client wrote or read it as serde does. With `pub enum Weather { Calm, Gale }` declared above it, `pub struct Logged { pub note: String, #[serde(flatten)] pub weather: Weather }` answers ``error: model_schema: field `weather` of `Logged` carries `#[serde(flatten)]` over `Weather`, which serde writes flattened as a plain enum: as a key named after the variant, holding null. TypeScript, Zod and the clients describe a plain enum as the variant's name, so none of them reads that key. Write the field as a named member so the value gets a key of its own, or flatten a type serde writes as an object. This refusal holds in every build with serde, and only a plain enum declared above reaches it: one declared below, or in another crate, is refused by the `const` beside the type that holds it, and one no `#[model_schema]` expanded is not refused, and where a schema surface is on it keeps its TypeScript and Zod intersection, and is refused by the JSON surface when the merge runs.`` An alias of a plain enum is refused the same way, and so is a variant that holds one beside the tag `#[serde(tag = "...")]` writes. So are a [brand](generics-and-brands.md#branded-newtypes) or a struct of one slot over a plain enum, a generic type declared above filled at one (`ProbeWrap<ProbeMood>` over `pub struct ProbeWrap<T>(T);`), a type whose value is one of those, and, flattened, an `Option` of any of them or in any of them, each named as written: ``carries `#[serde(flatten)]` over `ProbeWrap<ProbeMood>`, which serde does not write as an object``. They were refused with the error of a value Serde writes as no object, which said what Serde writes does not join the object, or cannot sit beside the tag; Serde writes each as the key naming the variant, holding `null`, and reads it back. A newtype variant beside the tag over one that writes an `Option` of a plain enum on the way is refused with the error of an `Option`.

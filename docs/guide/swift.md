### `validate()` in the Swift client

Every Swift type `swift_definition()` writes has `public func validate() -> [String]`: a struct, a tuple struct, a unit struct, the wrapper of a [branded newtype](generics-and-brands.md#branded-newtypes), an enum under every tagging and a plain one, a type with a parameter at every filling, and the struct written for a variant's named members or for a tuple. It answers one message per broken rule, and an empty list for a value that keeps every one. It judges a value built or changed in code, and `init(from:)` of the type calls it on the value it read, so [a read refuses what it refuses](#a-swift-read-refuses-what-validate-refuses).

```swift
let parcel = Parcel(label: "", itemCodeList: ["x", "x"], fragileItemCodes: [])
let violations = parcel.validate()
// ["'label': too short: minimum length is 1, got 0", "'itemCodeList': duplicate item code x"]
```

A type with no rule, which holds no type that has one, declares `public func validate() -> [String] { [] }`.

**What runs** is what the Rust [`validate()`](validation.md#the-validate-method) of the type runs, in its order and in its words: what the value a member holds reports, then the member's bounds, then the checks it names, member by member as declared, and the type's own checks last. A bound written on a member runs beside the bounds its type declares, the member's first.

| Written in Rust | What Swift runs |
|---|---|
| `minLength`, `maxLength` on a string | `value.unicodeScalars.count`: the string is counted in Unicode code points |
| `minLength`, `maxLength` on a list | `value.count` |
| `minimum`, `maximum` | `value < N`, `value > N` |
| `pattern`, and an enum's own beside a field's | `value.range(of: "...", options: .regularExpression) == nil`: a match anywhere in the string |
| [`literal`](literals-and-type-names.md#literal-values) | `value != 214`, `value != "fixed"`, `!value`: on each item of a list, under its index |
| `check = ["withinParcel"]` | `withinParcel(value)`, the Swift function of that name |
| a `HashSet`, a `BTreeSet` or an `IndexSet`, with no key | `Parcel.swiftSchemaRepeats(value)`, ahead of the set's count: two items are one where `JSONEncoder` with sorted keys writes one text for both, and the message is [`repeats an item: a set holds each item once`](models.md#a-set-holds-each-item-once) |

- **The unit of a length is the Unicode code point**: `"é"` counts 1, `"e\u{301}"` 2, and a character outside the Basic Multilingual Plane 1. The Rust `validate()` measures a string with `len()`, its bytes in UTF-8, so the two agree on ASCII text and differ beyond it.
- **A whole float is quoted back without `.0`**, as Rust writes it: `2.0` reads `got 2`.
- **An `Option` is measured where it holds a value.**
- **A range no value of the type can break is not written**: `minimum = 0` on a `u32` adds no comparison, which Swift would warn of.
- **A pattern is read by Foundation's regular expressions**, so a type that carries one needs `import Foundation`. Two constructs are written another way for that engine to read the pattern as the `regex` crate does: `$` as `\z`, since it otherwise also matches ahead of a line terminator that ends the string, and `\v` as `\u000B`, since it is otherwise every vertical space. The message quotes the pattern as you wrote it.
- **A branded newtype runs its own bounds on the value it wraps**, under no path. One that declares a parameter runs them where the value is of its declared default's Swift type (`value as? String`), and at no other filling. A declared default that is itself a brand written with arguments, `default_types(WrapType = StrictDocumentId<String>)`, is told by `value as? StrictDocumentId<String>`, which Swift keeps the arguments of, and the bounds measure the value that brand holds. A `String`, a `PathBuf` and a `char` are all a Swift `String`.
- **A bound on a field typed with a brand** measures the text the brand's wrapper answers with `swiftSchemaBoundText`, a member every brand over a string or a path has, and a length counts what it answers with `swiftSchemaBoundLength`, which a brand over a string, a path or a list has; a brand over a brand answers through the brand it holds. The brand is declared above the field's type or below it. A bound on a field typed with an alias of a string measures the string, and a length on one typed with an alias of a list counts its items.

**A type that holds another** runs its `validate()` and writes each message under the place it holds it at:

```swift
errors += firstParcel.validate().map { Manifest.swiftSchemaUnder("firstParcel", $0) }
for (index, held) in parcelList.enumerated() { errors += held.validate().map { Manifest.swiftSchemaUnder("parcelList.\(index)", $0) } }
for (key, held) in parcelsByDock.sorted(by: { $0.key < $1.key }) { errors += held.validate().map { Manifest.swiftSchemaUnder("parcelsByDock.\(key)", $0) } }
if let held = spareParcel { errors += held.validate().map { Manifest.swiftSchemaUnder("spareParcel", $0) } }
```

A Swift dictionary keeps no order, so a map is walked by its sorted keys. A value behind a type parameter is not reached, as in Rust. `swiftSchemaUnder` is a private function written into each type that names a place: nothing is shared between two emitted types, and nothing is declared beside them.

**The path a message names** is the steps serde writes on the way to the value, joined by dots: a key, a position in an array, or nothing where serde writes the value itself.

| Member | serde writes it | The name |
|---|---|---|
| a named field of a struct | under its key | `'itemLabel'` |
| a slot of a tuple struct of several slots | at its position in the array | `'1'` |
| the one slot of a struct serde writes as the value itself | as the value itself | none: the sentence alone, or the holder's key alone |
| a named member of a variant, no tag attribute | `{"Loose":{"freightLabel":…}}` | `'Loose.freightLabel'` |
| the one slot of a variant, no tag attribute | `{"Boxed":…}` | `'Boxed'`, and `'Boxed.itemLabel'` for a model it holds |
| a slot of a variant of several, no tag attribute | `{"Split":[…]}` | `'Split.1'` |
| a named member, tag and content key | `{"kind":"Loose","held":{…}}` | `'held.haulLabel'` |
| the one slot, tag and content key | `{"kind":"Boxed","held":…}` | `'held'` |
| a slot of several, tag and content key | `{"kind":"Split","held":[…]}` | `'held.1'` |
| a named member, tag alone | beside the tag | `'liftLabel'` |
| the one slot, tag alone | its own keys beside the tag | none |
| a member of an untagged variant | as the value itself, or under its key | none for a slot, its key for a named member |

**The functions you write** are any functions of the module the generated types are compiled in. A check is called under the name the attribute writes:

| | Swift |
|---|---|
| A field's check | `func withoutDuplicates(_ value: [String]) -> [String]` |
| A type's check | `func withinParcel(_ value: Parcel) -> [String]` |
| The check of a type with a parameter, written once | `func withACode<CodeType>(_ value: Crate<CodeType>) -> [String]` |

```swift
func withoutDuplicates(_ value: [String]) -> [String] {
  var seen = Set<String>()
  for code in value where !seen.insert(code).inserted {
    return ["duplicate item code \(code)"]
  }
  return []
}

func withinParcel(_ value: Parcel) -> [String] {
  value.fragileItemCodes.enumerated()
    .filter { !value.itemCodeList.contains($0.element) }
    .map { "'fragileItemCodes.\($0.offset)': \($0.element) is outside of itemCodeList" }
}
```

A function answers one message per broken rule, and an empty list for none. A field's check takes the field's own value, under an `Option` only where one is held, and names no path: `validate()` writes each message under the field. A type's check takes the whole value and leads each message with the path of what it refuses, as [in Rust](checks.md#the-messages). A name with no function does not build:

```text
error: cannot find 'withinParcel' in scope
```

**What you declare.**

- **A field named `validate`** is declared `validate_`, the method having the name, and keeps its key: `case validate_ = "validate"`.
- **A type tixschema has not written** is one a holder cannot tell from a model declared below it, so it calls its `validate()` and reads it through its `init(swiftSchemaUnjudged:)`: a type of your own that a generated type holds declares `func validate() -> [String] { [] }`, `func swiftSchemaValidateBound() -> [String] { [] }` and `init(swiftSchemaUnjudged decoder: Decoder) throws { try self.init(from: decoder) }`. An alias of a type that has none (`type LaterTitle = String;`) is declared above the type that holds it. Declared below, the Swift compiler answers `value of type 'LaterTitle' (aka 'String') has no member 'validate'`.
- **A type alias of a list, a map or an `Option` is declared above every type whose field names it.** Declared below, the holder reads it as a model, and the emitted Swift does not compile: `incorrect argument label in call (have 'swiftSchemaUnjudged:', expected 'from:')` and `value of type 'ProbeList' (aka 'Array<String>') has no member 'validate'`. Move the alias above the holder.
- **An alias of a string that a field bounds** is declared above that field's type. Declared below, it is a name the emitter reads as a brand, and the Swift compiler answers `value of type 'LaterTitle' (aka 'String') has no member 'swiftSchemaBoundLength'`, or `'swiftSchemaBoundText'` for a pattern. The same error answers a length or a pattern on a field typed with a struct or an enum, which holds no string to measure.

#### A Swift read refuses what `validate()` refuses

`init(from:)` of every type `swift_definition()` writes reads the type and then calls `validate()` on the value it read, as [the Rust read](validation.md#a-read-refuses-what-validate-refuses) does. A payload whose value breaks a bound or a check is thrown as `DecodingError.dataCorrupted`, and no value is handed back:

```swift
do {
  let manifest = try JSONDecoder().decode(Manifest.self, from: payload)
  carry(manifest)
} catch DecodingError.dataCorrupted(let context) {
  print(context.debugDescription)
}
```

The `debugDescription` is the list `validate()` answers of the value read, every message, joined by `; `. A manifest that holds a broken parcel in a field, a list, a map and an optional is refused once, each message at its full path. The error is one line, broken here after each `; `:

```text
'firstParcel.label': too short: minimum length is 1, got 0;
'parcelList.1.fragileItemCodes.1': y is outside of itemCodeList;
'parcelsByDock.north.label': too short: minimum length is 1, got 0;
'spareParcel.fragileItemCodes.1': y is outside of itemCodeList
```

The text holds no coding path. `codingPath` is the decoder's own, as for every decoding error: empty for the value the read was asked for, and `1` for the second manifest of a `[Manifest]`.

**What the emitter writes.** Every struct and every enum has two initializers that read it:

```swift
public init(swiftSchemaUnjudged decoder: Decoder) throws {
  let container = try decoder.container(keyedBy: CodingKeys.self)
  self.label = try container.decode(String.self, forKey: .label)
  self.itemCodeList = try container.decode([String].self, forKey: .itemCodeList)
  self.fragileItemCodes = try container.decode([String].self, forKey: .fragileItemCodes)
}

public init(from decoder: Decoder) throws {
  try self.init(swiftSchemaUnjudged: decoder)
  let violations = validate()
  if !violations.isEmpty {
    throw DecodingError.dataCorrupted(DecodingError.Context(codingPath: decoder.codingPath, debugDescription: violations.joined(separator: "; ")))
  }
}
```

- **`init(swiftSchemaUnjudged:)` is the read alone.** It builds the value from the same payload and judges nothing. It is what a type that holds another reads it with, and what reads a value that is to be repaired: call it from an `init(from:)` of your own, which is where a `Decoder` is handed out.
- **Every struct declares its memberwise initializer**, `public init(label: String, itemCodeList: [String], fragileItemCodes: [String])` here: the one Swift synthesizes is gone once a struct writes an `init(from:)`. A value built with it is judged when you call `validate()`.
- **`encode(to:)` judges no bound and no check.** Swift synthesizes it where it did, and the emitter writes it for a type that holds a `char` or a chrono date, time, or date and time, each held as a `String`, which it writes in [the form every target reads](client-forms.md#the-form-each-client-sends): a `NaiveDateTime` with a `Z`, and a `NaiveTime` or a `NaiveDateTime` without seconds, is written in the form serde writes, and a text no such rewrite turns into its form is refused with `EncodingError.invalidValue`, `expected a character, found "ab"` or `expected a date, found "2024-1-5"`, under the encoder's coding path.
- **A brand and a tuple struct that declares one slot write their value through their own encoder**, as serde writes it, so a flattened one joins its value's keys to the holder's object. With `pub struct Baled(pub Bale);` over `pub struct Bale { pub label: String }`, flattened beside `count: u32`, the holder is written `{"label":"l","count":2}`.
- **A `char` and a chrono date, time, and date and time are read in their one form**, as TypeScript and Zod read each: `"ab"` for a `char` is refused with `DecodingError.dataCorrupted` and `expected a character, found "ab"`, as serde refuses it, and a text `z.iso.date()`, `z.iso.time()` or `z.iso.datetime({ local: true })` refuses with `expected a date, found ...`, `expected a time, found ...` or `expected a date and time, found ...`, the value quoted as JSON, under the decoder's coding path, and a map's key under the path of its entry. Where serde and Zod part on a date, the read follows Zod: it refuses `2024-1-5`, which serde reads, and reads `2024-01-05T10:20Z`, which serde refuses. A `DateTime<Tz>` is a `Date`, read from RFC 3339 with or without a fraction of a second, and written as chrono writes it: no fraction for a date of whole seconds, `2024-01-05T10:20:30Z`, and three digits of one otherwise, `2024-01-05T10:20:30.500Z`. Swift holds a millisecond: a date finer than that is read at the millisecond, and a map keyed by dates that read as one key is refused with `repeated key ...` under the entry, where it kept one entry. `validate()` names a date key as serde writes it, fraction included. Under `as_number` it is an `Int64`, the number serde writes. An integer is held in its own type, which holds its range.
- **A struct's member under `#[serde(skip_serializing)]` is read, and encoded under no key**, as serde writes none, and a flattened one encodes nothing into its holder. A flattened one that is no `Option` is read as any flattened member is, its `default` aside, as serde reads it: a payload without a key its struct requires, or with an entry its map does not read, is refused. A struct that holds a member under `skip_serializing` has an `encode(to:)` tixschema writes in place of Swift's, which would encode every property. A member under `skip_serializing_if` is encoded wherever it holds a value: `encode(to:)` cannot call the Rust function, so under any function but `Option::is_none`, `Vec::is_empty` say, it encodes the key where serde leaves it out.
- **A plain enum that names no check** keeps the `init(from:)` Swift synthesizes, and its `init(swiftSchemaUnjudged:)` is that read.

**A type that holds another reads it with no judgement**, handed a decoder of its own, so the whole value is judged once, by the type the read was asked for:

```swift
_ = try container.decodeNil(forKey: .firstParcel)
self.firstParcel = try Parcel(swiftSchemaUnjudged: container.superDecoder(forKey: .firstParcel))

var listed = try container.nestedUnkeyedContainer(forKey: .parcelList)
var items: [Parcel] = []
while !listed.isAtEnd { items.append(try Parcel(swiftSchemaUnjudged: listed.superDecoder())) }
self.parcelList = items

let keyed = try container.nestedContainer(keyedBy: SwiftSchemaAnyKey.self, forKey: .parcelsByDock)
var entries: [String: Parcel] = [:]
for entry in keyed.allKeys { entries[entry.stringValue] = try Parcel(swiftSchemaUnjudged: keyed.superDecoder(forKey: entry)) }
self.parcelsByDock = entries

if container.contains(.spareParcel), try !container.decodeNil(forKey: .spareParcel) { self.spareParcel = try Parcel(swiftSchemaUnjudged: container.superDecoder(forKey: .spareParcel)) } else { self.spareParcel = nil }
```

`SwiftSchemaAnyKey` is a private key type written into each type that reads a map entry by entry. A value is read with no judgement exactly where the `validate()` of its holder runs its `validate()`. Anywhere else it is read through `Decodable` and judges itself: the first broken one ends the read with its own messages, under the coding path it sits at.

| Held | Judged |
|---|---|
| in a field, an optional, a list, a map's value, a tuple, a flattened member or the payload of a variant, in any nesting of those | once, with its holder, each message at its full path |
| under one of the holder's type parameters | by itself, as it is read: a `Crate<Parcel>` whose second parcel is broken is refused with `'fragileItemCodes.1': y is outside of itemCodeList`, under the coding path `codes`, `1` |
| as the value a brand wraps | by itself, as it is read |

- **An absent key and a `null` are read as they were.** A key a struct requires is still `keyNotFound` where it is absent, which is what the first statement above is for: `superDecoder(forKey:)` answers a decoder over `null` for an absent key. An optional member is still `nil` for an absent key and for a `null`. A key under `#[serde(default)]` is read as its default where it is absent ([A Key Read as Its Default](models.md#a-key-read-as-its-default-serdedefault)).
- **An `#[serde(untagged)]` enum takes the variant serde takes.** Its `init(swiftSchemaUnjudged:)` takes the first variant whose payload reads and whose own bounds hold: a bound written on a member, and the `pattern`, `minLength` and `maxLength` of a [brand](generics-and-brands.md#branded-newtypes) the member holds, which the brand's wrapper answers for alone with `swiftSchemaValidateBound()`. A check and a model the variant holds choose nothing: the variant is taken, and `init(from:)` then refuses the value. The enum asks every named type it holds, whatever order they are declared in, and every generated type answers: a type with no bound of its own answers `[]`. A variant over an `Option` reads `null` as holding `nil`, as serde reads it as holding `None`, and writes it back as `null`: with `#[serde(untagged)] enum Fathom { Count(Option<u32>), Flag(bool) }`, `null` is read as `.count(nil)`. Where two variants read `null`, the first takes it, as serde's read does. A variant over an alias of an `Option` reads it the same way.
- **An externally tagged enum is read from an object of one key, or a unit variant from its name**, as serde reads it. With `enum Hatching { Bay { label: String }, Calm, Dock { label: String } }`, `{"Bay":{"label":"n"}}` reads `Bay` and `"Calm"` reads `Calm`. An object of several keys, `{"Bay":{"label":"n"},"Dock":{"label":"s"}}` or `{"Bay":{"label":"n"},"north":2}`, is refused with `DecodingError.dataCorrupted` and `more than one key for Hatching`, and `{}` with `empty object for Hatching`, as serde and the generated Zod schema refuse each.
- **A fixed array `[T; N]` and a tuple are read from an array of their length alone**, as serde and the generated Zod schema read each. With `struct Clenching { pair: [u8; 2] }`, `{"pair":[1,2,3]}` is refused with `DecodingError.dataCorrupted` and `invalid length 3, expected 2`, and `{"pair":[1]}` with `invalid length 1, expected 2`, at the coding path of the array, `pair`, by `init(from:)` and by `init(swiftSchemaUnjudged:)`. A `[[u8; 2]; 3]` refuses an inner array of another length in the same words, at the path of that array, and the outer one at its own. A level written as `[T; N]` is read item by item wherever it is held: in a field, an optional, a map's value, a tuple's slot, a variant's payload, a tuple struct of one slot, a brand, a member a [`preprocess`](preprocess.md#preprocess-in-the-swift-client) corrects, an alias declared above its holder and a type argument. A fixed array that fills a type parameter is held in a wrapper, `{Holder}{Field}Argument{N}Fixed`, whose `value` is the array, as the type it fills reads it through `Decodable`. An alias declared below its holder, or in another crate, and one that declares a parameter, are read through `Decodable`, which takes an array of any length. With `struct Thawing(String, u32)`, `["b",1,2]` is refused with `invalid length 3, expected 2` and `["b"]` with `invalid length 1, expected 2`, and so is the array of a member's tuple, of a tuple a tuple holds and of a variant of several slots: the tuple is held to the length its decoder knows of the array, which `JSONDecoder` knows. An `#[serde(untagged)]` enum takes the variant serde takes: with `enum Grappling { Pair([u8; 2]), Spread(Vec<u8>) }`, `[1,2,3]` reads `Spread`.
- **An enum under a tag and a content key reads a unit variant from an object with no content key**, as TypeScript and Zod read it: with `#[serde(tag = "kind", content = "held")] enum Becalming { Breeze(bool), Lull }`, `{"kind":"Lull"}` reads `Lull`, and `{"kind":"Lull","held":5}` is refused with `DecodingError.dataCorrupted` and `Becalming: Lull takes no value`, as serde refuses it. `{"kind":"Lull","held":null}` is refused with the same error, as TypeScript and Zod refuse it, where serde reads `Lull`. serde writes the variant as its tag alone, so every payload serde writes is read.
- **A struct under its own `#[serde(tag = "...")]` reads a payload whose tag is the struct's name, and refuses any other**, as TypeScript and the generated Zod schema refuse it, whose tag is the literal of that name. serde reads the struct whatever the tag holds, and where it is absent, and writes the name back. With `#[serde(tag = "kind")] struct Flag { label: String }`, `{"kind":"Flag","label":"n"}` reads, `{"label":"n"}` is refused with `DecodingError.dataCorrupted` and ``missing field `kind` ``, `{"kind":"Other","label":"n"}` with `expected tag "Flag", found "Other"`, and `{"kind":5,"label":"n"}` with `expected tag "Flag", found 5`, where serde reads each as `Flag { label: "n" }`. The value found is quoted as JSON. A struct that names a [`preprocess`](preprocess.md#preprocess-in-the-swift-client) on itself reads the tag of what its functions answer. A struct with a `#[serde(flatten)]` member reads its tag the same way, and so does a struct flattened into a holder, from the object the holder hands it, so the holder refuses the same payloads. `encode(to:)` writes the tag with the struct's name, as serde writes it.
- **A `#[serde(flatten)]` member is read at its place, in the order declared**, as serde reads it. Every flattened member, the first one included, is handed the object without the keys the holder's own members take, those each struct flattened ahead of it took and those a holder of that holder took: the function a flattened member names is handed it, and so is a struct that names a [`preprocess`](preprocess.md#preprocess-in-the-swift-client) on itself. Every other struct, and an enum under a tag key, declared above its holder is read from the whole object, as TypeScript and the generated Zod schema read it; a key it reads that a member of its holder's own, a struct flattened ahead of it or the tag of the variant that flattens it reads too is refused at expansion ([Order and strictness of flattened members](flatten.md#order-and-strictness-of-flattened-members)). Any other type, a struct declared below its holder among them, is read from the object without those keys, a model the holder's `validate()` walks unjudged, and refused where it reads one of them, as serde refuses it. A struct with a `#[serde(flatten)]` member of its own hands the members it flattens the object without those keys and reads its own members from the whole object. A payload whose keys collide with none of those reads as it did before. A struct takes the keys it reads. A struct that names a [`preprocess`](preprocess.md#preprocess-in-the-swift-client) on itself, a flattened member that names one and a struct with a `#[serde(flatten)]` member of its own take no key, as serde reads each. A struct declared below its holder, or in another crate, is not known to take any: a member flattened after it is read from its keys as well, where serde reads it without them. A map is the [one member of its object](flatten.md#intersection-types-serdeflatten), and is read entry by entry, without the keys the types around its holder took, the tag of an enum under a tag key among them. A map under a key Swift wraps is read by its wrapper, through an `init(swiftSchemaUnjudged:swiftSchemaWithout:)` tixschema writes for it in an extension. An optional map is refused at expansion, as serde reads its `None` back as a map of no entry ([Order and strictness of flattened members](flatten.md#order-and-strictness-of-flattened-members)). A model a map holds is read with no judgement, so one that breaks its rule still refuses the payload, as serde refuses it. `encode(to:)` writes each flattened member at its place, a map under a key Swift wraps through its wrapper and a map of dates as the text serde writes. A flattened `Option` writes the keys of the value it holds beside its holder's, and nothing for `nil`, as serde writes nothing for `None`.
- **A plain enum under `#[serde(flatten)]` declared below its holder is read from the one entry named for its variant, over `null`, and written as that entry**, as serde reads and writes it. The holder is written before the enum is, so it cannot tell a plain enum from a struct: it reads the member from the object without the keys taken around it, and the one entry over `null` whose key reads as a plain enum of the member's type becomes that key. With `pub struct Casement { pub width: u32, #[serde(flatten)] pub weathering: Weathering }` over `pub enum Weathering { Sound, Worn }` declared below it, `{"Sound":null,"width":1}` reads `Sound` into the member and is written back as it was, and so are a variant read under its `alias`, the enum under a `rename_all`, the enum optional, and the member ahead of the holder's own. A payload with no entry named for a variant, one whose entry holds a value other than `null`, and one with entries under two variants' names are refused with `DecodingError.typeMismatch` (`Expected to decode String but found a dictionary instead`), where serde refuses the first two and reads the first of the third. A brand over a `String` flattened below its holder is no enum, and is refused, as serde refuses it. A plain enum declared above its holder is refused by the macro, as [Intersection Types](flatten.md#intersection-types-serdeflatten) says.
- **A flattened externally tagged enum takes one entry**, as serde reads it: the one under the name a variant is read under, its `rename` or the enum's `rename_all` included, or an alias of one, wherever it is in the object the enum is handed, and the enum is read from that entry. Every member flattened after it is handed the object without that entry. With `enum Hatching { Bay { label: String }, Calm, Dock { label: String } }` flattened in `struct Stowing { note: String, #[serde(flatten)] hatching: Hatching }`, `{"north":2,"Bay":{"label":"n"},"note":"a"}` reads `Bay` and the note `a`, and `{"Calm":null,"note":"a"}` reads `Calm`: a unit variant's entry is read over `null` alone, as TypeScript and Zod read it, where serde reads `{"Calm":{}}` too. Flattened ahead of a member that names a function, `{"Bay":{"label":"n"},"north":2}` reads `Bay`, and the function is handed `north`. A payload with no such entry is refused with `DecodingError.dataCorrupted` and `no variant of enum Hatching found in flattened data`, as serde refuses it, and an optional enum reads `nil` from it; an entry the enum does not read refuses the payload, as TypeScript and Zod refuse it, where serde reads `None`. A model the holder's `validate()` walks is read from the entry with no judgement, and judged once, with its holder. The enum is written as serde writes it, its variant's entry beside the holder's members, and a unit variant as its name over `null`: `Stowing(note: "a", hatching: .calm)` writes `{"note":"a","Calm":null}`, the enum optional or under a `preprocess` of its member as well. Under a `preprocess` of its member the enum is read from what the functions answer, a unit variant's entry over `null` among it, as the Zod schema reads it: `{"note":"a","Calm":null}` reads `Calm`. An enum under a tag key alone and an untagged enum take no key, as serde reads each, and so does an enum that names a [`preprocess`](preprocess.md#preprocess-in-the-swift-client) on itself or on its member. An enum under a tag and a content key takes both, as serde reads it as a struct of the two: a member flattened after it that is handed the object without the keys taken is handed neither. An enum declared below its holder, or in another crate, is not known to take an entry: it is read from the object it is handed, and is refused where that object holds any other key, as TypeScript and the generated Zod schema refuse the payload, where serde reads past the key: with `Hatching` declared below `Stowing`, `{"note":"a","Bay":{"label":"n"},"north":2}` is refused with `more than one key for Hatching`, and `Stowing(note: "a", hatching: .calm)` writes `{"note":"a"}`, with no entry for its unit variant, where serde writes `{"note":"a","Calm":null}`.
- **An externally tagged enum held by a newtype variant under a tag alone is read from the object without the tag and written beside the tag**, as serde writes it, a unit variant as its name over `null`: with `#[serde(tag = "kind")] enum Docketed { External(Palleted) }` over `enum Palleted { Loose, Stacked { layers: u32 } }`, `{"kind":"External","Loose":null}` reads `.external(.loose)` and is written back as it was read. The tag alone, `{"kind":"External"}`, is refused with `DecodingError.dataCorrupted` and `empty object for Palleted`, and the entries of two variants with `more than one key for Palleted`, as serde refuses each. An alias of the enum declared above is read and written the same way, held there or flattened.
- **`()` is read from `null` alone and written as `null`**, as serde reads and writes it, through a struct the client writes for each place it is held, named after that place (`ProbeUnitsUnitTuple` for the field `unit` below): a field, the slot of a brand, a list's item, a tuple's position, an `Option` and a variant's one value. With `struct ProbeUnits { listed: Vec<()>, nothing: ProbeNothing, paired: (u32, ()), unit: () }` and `#[serde(transparent)] struct ProbeNothing(())`, `{"listed":[null],"nothing":null,"paired":[1,null],"unit":null}` is read and written back as serde writes it. Any other value in its place is refused with `DecodingError.dataCorrupted` and `invalid type: [], expected unit`, the value quoted as JSON, and an absent key that holds `()` with the `keyNotFound` Swift's own read throws, as serde refuses each. An `Option<()>` reads `null` as `nil`, as serde reads it as `None`. A tuple struct whose every slot serde skips is no `()`: it is read from `[]` and written as `[]`, as serde writes it.
- **A name serde writes is read and written as serde writes it, whatever it holds.** A member's, an alias's, a struct's own tag key and name, an enum's variant, tag key and content key, and a plain enum's value are each written between the quotes of a Swift string, a `"` and a `\` escaped: with `#[serde(tag = "ki$nd", rename = "Price's$Tag\\")] struct Tariffed { #[serde(rename = "back\\slash")] backslash: String, #[serde(rename = "cost$usd", alias = "cost's")] cost: String, #[serde(rename = "say \"hi\"")] quoted: String }`, `CodingKeys` declares `case quoted = "say \"hi\""`, and `{"ki$nd":"Price's$Tag\\","back\\slash":"b","cost$usd":"c","say \"hi\"":"s"}` is read and written back as serde writes it.
- **A name serde reads beside the one it writes is read too.** A variant is read under each of its `#[serde(alias = "...")]` names, under every tagging, flattened, and in a plain enum, and a member under each of its aliases, in a struct, flattened or not, and in a variant. Each is written under the name serde writes. With `#[serde(alias = "Quay")] Dock { #[serde(alias = "name")] label: String }`, `{"Quay":{"name":"s"}}` reads `Dock` and is written back `{"Dock":{"label":"s"}}`. A member under two of its names, `{"Dock":{"label":"s","name":"t"}}`, is refused with `DecodingError.dataCorrupted` and ``duplicate field `label` ``, as serde refuses it. A flattened struct takes each alias of its members off its holder's object, and a member flattened after a member of its holder's own under an alias is handed the object without each of that member's names, as serde does. A struct reads a member under an alias from a container of every key, `let aliased = try decoder.container(keyedBy: SwiftSchemaAnyKey.self)`, under the one name the payload holds it under, and a plain enum with a variant under an alias declares its own `public init?(rawValue: String)`, which takes each alias, so every read of its raw value takes them, the key of a map among them. A type that names no alias is written as it was. An externally tagged enum read alone refuses a unit variant's entry over `null` under each of its names: with `#[serde(alias = "Still")] Calm`, `{"Still":null}` is refused with `unknown tag Still` as `{"Calm":null}` is, as TypeScript and the generated Zod schema refuse both, where serde reads `Calm`.
- **A payload with entries under two of a flattened enum's names is refused**, where serde reads the first entry in the object's order. Swift keeps no order of an object's keys, so it cannot tell which entry is the first. `{"note":"a","Bay":{"label":"n"},"Dock":{"label":"s"}}` is refused with `DecodingError.dataCorrupted` and `more than one variant of enum Hatching found in flattened data: Bay, Dock` at the holder's coding path, each variant named once, in the order the enum declares them, whatever order the payload holds them in, and so is a variant's entry beside an entry under its alias, naming that variant alone, the enum optional too. The Dart and Kotlin reads refuse each such payload in the same words. TypeScript refuses that payload as well, `error TS2322: Type '{ note: string; Bay: { label: string; }; Dock: { label: string; }; }' is not assignable to type 'Stowing'.`, and so does the generated Zod schema, with `Invalid input`.
- **A flattened `Option` of any type but a map is read as `nil` where the object it is handed holds none of that type's keys, and a key there that does not read refuses the payload**, as TypeScript and Zod refuse it, where serde reads `None` and drops the key with no error. With `struct Flaking { #[serde(flatten, default, skip_serializing_if = "Option::is_none")] tabling: Option<Tabling> }` over a `Tabling` that reads `label`, `{}` is read with `tabling` `nil` and `{"label":"north"}` with the `Tabling` it holds, and `{"label":5}` is refused, where serde reads `None`. A struct of two keys is refused where one of them is there and the other is not. The keys are those serde reads the type under, each member's name and each alias, and they are looked for in the object the type is read from: the whole object for a struct, or an enum under a tag key, declared above its holder that names no function, a key a member of its holder's own reads too among them, as Zod looks for them, where serde reads `None`. An externally tagged enum is `nil` where the object holds no entry under one of the names its variants are read under, an enum under a tag key alone where it holds no tag, and an enum under a tag and a content key where it holds neither, and each is refused where one of those is there and the enum does not read it: with `#[serde(tag = "kind", content = "body")] enum Becket { Calm, Round { turns: u32 } }` flattened beside `note`, `{"note":"n"}` reads `nil`, and `{"kind":"Gale","note":"n"}` and `{"body":{"turns":2},"note":"n"}` are refused, where serde reads `None`. A type whose keys are not known is read as `nil` wherever its read throws, as serde reads `None`: a struct declared below its holder or in another crate, a struct that reads no key of its holder's (one with a `#[serde(flatten)]` member of its own, one that names a [`preprocess`](preprocess.md#preprocess-in-the-swift-client) on itself, one with no member serde reads), an untagged enum, an enum declared below its holder or in another crate, an enum that names a [`preprocess`](preprocess.md#preprocess-in-the-swift-client) on itself, an alias, and a type parameter filled at any type but those that follow. A type parameter is looked for by the keys of the type that fills it, as an `Option` of that type is above, where that type is an `ObjectId`, a brand or a struct of one slot over one that declares no parameter, or a struct or an enum under a tag key whose keys are known, written above the type that flattens the `Option`, told by its name as it is read: with `struct Waxing<Held> { #[serde(flatten)] annotation: Notation, #[serde(flatten)] held: Option<Held> }`, `Waxing<ObjectId>` reads `{"note":"n"}` with `held` `nil` and refuses `{"$oid":"507f1f77bcf86cd79943901z","note":"n"}`, as TypeScript and Zod refuse it, where serde reads `None`. A model the holder's `validate()` walks is read with no judgement where it reads, so one that breaks its rule still refuses the payload, as serde refuses it. A flattened `Option` that names a [`preprocess`](preprocess.md#preprocess-in-the-swift-client) is read as the Zod schema of its holder reads it: its functions are called first, on the object the member is handed, and the type is read from what they answer. Where that read throws, an answer of `null` among it, it is `nil` where that object holds none of a struct's keys, or no key at all for a type whose keys are not known, an enum among them, and the payload is refused where the object holds one. With `struct Reeved { note: String, #[model_schema_prop(preprocess = ["asGiven"])] #[serde(flatten, default, skip_serializing_if = "Option::is_none")] tholepin: Option<Tholepin> }` over a `Tholepin` that reads `label`, and `func asGiven(_ payload: Any) -> Any { payload }`, `{"label":"north","note":"n"}` reads that `Tholepin`, `{"note":"n"}` reads `nil`, where serde refuses it with `missing field`, and `{"label":5,"note":"n"}` is refused. Under a function that answers `NSNull()`, `{"label":"north","note":"n"}` is refused, as Zod refuses it, where serde reads `None`.
- **What a variant under a tag alone holds is read from the object without the tag**, as serde reads it: serde takes the tag off the object and hands the variant the rest. The type a variant holds as its one slot, and each member a variant flattens, beside a member of its own or alone, are read from that object: a type that takes the keys the types around it took through `init(swiftSchemaUnjudged:swiftSchemaWithout:)`, the tag among those keys, and any other through [`SwiftSchemaPayload`](preprocess.md#preprocess-in-the-swift-client), from the object without them. A struct, and an enum under a tag key, declared above the enum and naming no function, is read from the whole object, the tag in it, as TypeScript and the generated Zod schema read it: with `#[serde(tag = "kind")] enum Grafting { Held { #[serde(flatten)] flag: Kinded }, Slot(Kinded) }` over a `Kinded` that reads `kind`, `{"kind":"Held"}` and `{"kind":"Slot"}` read the tag into `kind` and are written back as they were, where serde refuses each with `missing field`. A model the enum's `validate()` walks is still read with no judgement.
- **The service clients answer the fault they had** for a reply that breaks a rule, the thrown error reaching the handling they have for a reply that does not read: `swift_http_client()` answers `undeserializable-payload` and `swift_ws_client()` answers `failed-validation`, each with the messages in its `detail`. The `failed-validation` fault names the field the Rust `ws_rpc` dispatcher names for the same payload, the steps of the `DecodingError`'s coding path, or the place a `validate()` message opens with; a number outside the range of its integer, which Foundation refuses with no coding path, names none. See [the field a refused message names](ws-rpc.md).
